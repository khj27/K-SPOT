# K-SPOT 개발 인수인계

## 구현된 기능

- 콘텐츠 탐색·상세·Kakao 지도, 관리자 진입과 Firebase 관리자 인증
- 콘텐츠 초안 등록·수정·공개, 공개 콘텐츠를 사용자 페이지에 반영
- CSV 일괄 등록 및 세로형 관광 조사표 변환·보완·검증
- 유튜브 URL 썸네일, 맞춤 추천과 추천 이유 표시
- 일정 생성·순서 변경·삭제·저장·다시 열기
- 일정의 촬영지별 주변 5km TourAPI 관광지 조회·추가·제외, Firebase 저장 및 다시 열기 (일정당 최대 10곳)
- 저장 장소, 마이페이지 현황, 최근 본 장소, 과거 로컬 자료의 Firebase 이전
- 일반 사용자 이메일 회원가입·로그인·로그아웃·비밀번호 재설정, 계정별 여행 자료 자동 저장 (`docs/user-accounts.md`). Firestore에 직접 저장하며 탭 복귀 및 30초 간격 조회로 변경사항을 불러옵니다.
- TourAPI 서버 호출·캐시·장애 안내 구현. 2026-09-19 로컬 인증키 등록 후 주변 30건 및 창의문 상세 설명·이미지 실제 응답 확인.

## 사용자가 준비할 항목

1. 관광공사 TourAPI 인증키: 현재 PC의 `.env.local`에는 등록 완료했습니다. 다른 노트북과 배포 호스팅에는 `TOUR_API_KEY`를 별도로 등록합니다. 공모전 증빙용으로 실제 주변 관광지 화면을 저장합니다.
2. 콘텐츠 사실 검수: 기생충 조사표를 관리자 CSV 화면에 업로드하고 위도·경도·검수일·이미지 사용 근거를 입력합니다. 초안 저장 후 관리자 장소 관리에서 내용을 검수하고 공개합니다. 현재 데모 촬영 관계는 사실 검증 자료가 아니므로 공모전 제출 전에 검증된 데이터로 교체해야 합니다.
3. 배포 계정과 도메인: Next.js 서버 실행을 지원하는 호스팅에 GitHub 저장소를 연결합니다. `.env.example`의 필요한 값을 호스팅 환경변수로 등록하고 배포합니다. Firebase 서비스 계정 개인키는 서버 전용 변수에만 넣습니다. 카카오 JavaScript 키의 허용 도메인과 Firebase Authentication의 승인된 도메인에 배포 도메인을 등록합니다.
4. 공개 운영 전 관리자 비밀번호를 본인이 정한 강한 비밀번호로 변경합니다. 테스트 계정 대신 실제 운영 관리자 이메일을 사용할 경우 Firebase 사용자와 서버의 `ADMIN_EMAILS`를 함께 맞춥니다.
5. 다른 노트북: `docs/another-laptop.md`대로 clone 또는 pull, `npm ci`, 개인적으로 전달한 `.env.local` 설정, `npm run dev` 순으로 실행합니다. 동일 사용자 계정으로 로그인하면 여행 자료를 자동으로 불러옵니다.

## 검증과 한계

로컬 검증은 `npm test`, `npm run lint`, `npm run build`로 수행합니다. 빌드에 TypeScript 검사가 포함됩니다. GitHub Actions에서도 같은 검사를 실행합니다.

2026-09-20 로그인한 브라우저에서 찜을 실제 Firestore에 저장하고 새로고침 후 유지를 확인했습니다. 관리자 신규 콘텐츠 공개, 모바일 실기기와 배포 환경 검수는 별도로 남아 있습니다.

현재 서비스는 한국어 MVP입니다. 영문 전체 화면, 교통수단에 따른 실제 이동 시간 계산은 구현 범위에 포함되지 않았습니다. 일정은 하루 한 장소를 추천합니다. 로컬 API 실연동은 확인했으며 배포 환경의 키 설정과 실연동 검증은 별도로 필요합니다.

2026-09-20 검증: 부산 근현대역사관 일정에서 실제 TourAPI 부산영화체험박물관을 추가하고, Firebase 저장 → 저장 목록 새로고침 → 일정 다시 열기에서 유지되는 것을 확인했다. 테스트 27개·lint·production build를 통과했다. 검증용 부산 일정 1건은 로그인 계정에 남겨두었다.
