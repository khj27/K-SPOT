# 일반 사용자 이메일 계정

## 사용자 흐름

1. 상단 로그인·가입 → 회원가입에서 이메일, 닉네임, 비밀번호를 입력합니다.
2. Firebase Authentication에 일반 사용자 계정이 생성됩니다. 관리자 권한은 부여하지 않습니다.
3. 마이페이지에서 현재 계정과 로그아웃 버튼을 확인합니다.
4. 로그인 전 자료가 필요하면 `이 브라우저의 비회원 자료 가져오기`를 누릅니다. 비회원 원본은 그대로 남습니다.
5. `계정 자료 확인` 후 `현재 자료와 합쳐 계정 저장`을 누릅니다.
6. 다른 기기에서 동일한 계정으로 로그인 → 계정 자료 확인 → 이 기기로 가져오기를 누릅니다.

계정 저장은 자동 동기화가 아닌 명시적 백업·가져오기입니다. 업로드에서 같은 일정 ID는 현재 기기 값으로 갱신하고, 가져오기에서는 현재 기기 값을 유지합니다. 삭제는 다른 기기나 계정에 자동 전파하지 않습니다. JSON 백업도 계속 사용할 수 있습니다.

## 인증과 데이터 경계

- 사용자 인증 쿠키 `kspot_user_session`은 httpOnly, SameSite=Lax이며 운영 환경에서는 Secure입니다. 유효 기간은 5일입니다.
- 로그인 토큰 검증과 최근 5분 이내 인증을 요구합니다. 계정 API의 모든 쓰기는 동일 출처 요청인지 확인합니다.
- Firebase 클라이언트 사용자 로그인은 관리자 로그인과 별도 인스턴스이며 메모리 인증을 사용합니다.
- 서버는 검증된 사용자 UID로만 `userTravel/{uid}`를 읽고 씁니다. 클라이언트가 다른 사용자 ID를 지정하면 거부합니다.
- Firestore 클라이언트 직접 접근 거부 규칙을 유지합니다. 새 규칙 배포는 필요하지 않습니다.
- 계정 백업은 400KB 이하이며 revision 트랜잭션으로 오래된 기기의 덮어쓰기를 차단합니다.
- 브라우저 저장 키는 비회원·각 사용자 UID별로 분리합니다. 로그아웃해도 로컬 사본은 해당 브라우저에 남으므로 공용 기기에서는 이용 후 브라우저 데이터도 정리해 주세요.

## 운영 설정과 확인

Firebase Authentication의 이메일/비밀번호 로그인이 활성화되어 있어야 합니다. 기존 관리자 이메일 로그인과 같은 Firebase 프로젝트를 사용합니다. 배포 시 승인된 도메인과 `.env.example`의 Firebase 클라이언트·서버 변수를 확인합니다.

비밀번호 재설정은 사용자가 폼에서 요청할 때만 Firebase 이메일을 발송합니다. 임의 사용자 계정 생성이나 테스트 메일 발송은 수행하지 않았습니다. 실제 회원가입·메일 수신·다른 기기의 계정 자료 저장/가져오기는 소유한 테스트 이메일로 확인해야 합니다.

이메일 인증 강제, 소셜 로그인, 회원 탈퇴 화면은 이번 구현에 포함되지 않습니다. 공개 운영 전에 개인정보 처리 안내와 계정 삭제 요청 처리 절차를 준비하세요.
