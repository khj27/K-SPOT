# 공모전 심사 관점 점검표

## 현재 평가

| 항목 | 배점 | 현재 판단 | 근거와 다음 조치 |
| --- | ---: | --- | --- |
| 서비스 구현성 | 30 | 중 | 탐색→상세→코스→저장 흐름은 작동한다. Kakao 지도, 관리자 등록·수정·공개 및 Firebase 사용자 저장을 구현했다. 배포 환경 검수가 필요하다. |
| 서비스 기획력 | 30 | 중상 | K-콘텐츠 팬덤을 비수도권 관광으로 연결하는 문제와 사용 흐름이 선명하다. 실제 사용자 검증 지표가 필요하다. |
| 데이터 활용 적절성 | 20 | 중 | TourAPI 주변 조회·상세와 관광지의 일정 추가·Firebase 저장을 구현했다. 배포 실연동 증빙이 필요하다. |
| 서비스 발전성 | 20 | 중상 | 콘텐츠·장소·TourAPI 분리 구조와 다국어 확장 방향이 있다. 운영 데이터 파이프라인과 수익/협력 모델을 구체화해야 한다. |

점수는 공식 심사 결과가 아니라 현재 저장소를 기준으로 한 개발 우선순위 판단이다.

## 제출 전 P0

- [ ] `TOUR_API_KEY`를 배포 환경에 설정하고 장소 상세의 실데이터 응답을 캡처한다.
- [ ] 근거가 확인된 비수도권 콘텐츠 장소 30곳 이상으로 데모 데이터를 교체한다.
- [ ] 각 콘텐츠-장소 관계에 출처 URL과 확인일을 입력한다. 이미지 출처·사용 근거는 선택적으로 기록한다.
- [x] 일정 결과에 사용자가 선택한 TourAPI 관광지를 포함하고 촬영지와 구분해 표시한다. (2026-09-20 실제 저장 확인)
- [ ] 실제 지도에서 마커, 현재 위치, 길찾기 링크를 검증한다.
- [ ] 심사용 3분 시나리오를 ‘콘텐츠 검색→근거 확인→주변 관광지→코스 생성→저장’ 순서로 고정한다.

## 제출 전 P1

- [ ] 관리자 인증과 장소 검수 상태(`draft → reviewed → published`)를 연결한다.
- [x] CSV 업로드에서 필수값·좌표·URL·중복을 검증한다.
- [ ] 영문 핵심 흐름을 제공하고 TourAPI 영문 서비스 fallback 정책을 문서화한다.
- [ ] 모바일 360px, 태블릿 768px, PC 1440px에서 주요 흐름을 확인한다.
- [ ] TourAPI 장애, 0건, timeout, 잘못된 키 화면을 각각 캡처한다.

## 발표에서 보여줄 차별점

1. 출처가 확인된 콘텐츠-장소 관계만 공개한다.
2. 촬영지 검색에서 끝나지 않고 TourAPI 주변 관광 자원으로 체류 동선을 확장한다.
3. 추천 결과에 지역·취향·비수도권 가중치를 표시해 사용자가 이유를 이해할 수 있다.
