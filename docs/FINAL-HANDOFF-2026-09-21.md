# K-SPOT 최종 정리 · 2026-09-21

## 이번 마무리

- 브라우저 제목과 기존 브랜드 표기를 K-SPOT으로 통일.
- 자동 저장되는 찜·최근 본 기록과 저장 버튼을 눌러야 하는 여행 일정을 안내에서 구분.
- 추천 점수 계산식 대신 사용자에게 필요한 추천 기준으로 문구 정리.
- 직접 입력한 장소의 지도 미표시 이유를 명확하게 안내.
- 삭제 실패를 확인창 안에서도 표시해 재시도 가능 여부를 확인할 수 있도록 개선.
- 예기치 않은 페이지 오류에 재시도·홈 이동 화면 추가.
- 저장 자료 조회 실패를 '자료 없음'으로 표시하지 않도록 보완.
- 공개 콘텐츠는 서버 프로세스에서 60초간 재사용하고 동시 조회를 하나로 합침. 관리자 생성·수정 성공 시 해당 프로세스 캐시 제거. 다른 프로세스는 최대 60초 후 반영.
- 계정 자동 조회는 화면이 보일 때 최대 분당 1회, 실패 후 5분 간격. 명시적인 다시 불러오기와 사용자 저장 동작은 즉시 요청.

## 운영 중 확인한 문제

Firestore에서 RESOURCE_EXHAUSTED(할당량 초과)를 실제 확인했습니다. 사용자의 할당량 조정 후 읽기 요청이 정상화됐습니다. 데이터 삭제 작업은 수행하지 않았습니다. 요금제·한도 설정 자체는 변경하지 않았습니다.

## 검증

- 자동 테스트 53개 통과: 인증·소유권, 저장·수정·삭제 로직, 기존 데이터 호환, 직접 입력 장소, 관광지 분류, 공개 콘텐츠 캐시 등.
- ESLint 통과.
- Next.js 프로덕션 빌드 및 TypeScript 검사 통과.
- 공개 주요 경로 10개 응답 확인. 관리자 미인증 접근은 로그인으로 이동하는 기존 흐름 유지.
- 로그인된 관리자 대시보드에서 공개 콘텐츠 32건 표시 확인.
- Git 추적 대상에 .env.local 또는 서비스 계정 JSON 없음(.env.example만 추적).
- 실제 사용자 자료의 삭제·테스트용 저장은 수행하지 않음. 실패·동시 저장 등은 자동 모의 테스트로 검증.

## 사용 방법

1. 관리자: 콘텐츠 장소에서 자료·주소·좌표·장소 분류를 확인한 뒤 공개. 콘텐츠 제보 메뉴에서 사용자 제보 확인.
2. 사용자: 원하는 장소를 찜하면 마이페이지에서 관리.
3. 여행 일정: 날짜·인원을 정하고, 주변 장소는 숙소/식사/놀거리 등으로 조회. 필요한 경우 직접 입력 장소 추가.
4. 일정을 편집한 뒤 반드시 '일정 저장'. 직접 입력 장소는 시간·메모와 함께 저장되지만 지도에는 표시되지 않음.

## 운영 전 남은 확인

- 서로 다른 실제 기기에서 같은 계정의 저장·재조회 확인.
- 관리자 등록 자료의 주소·사진·분류 정확성 최종 검수.
- Firebase 사용량을 운영 중 확인. 이번 조회 감소가 향후 할당량 초과를 보장하여 방지하는 것은 아님.
- TourAPI 장소 분류는 조회된 결과 안에서 작동하며 주변 모든 업체를 전수 제공하지 않음.
- 영어 UI를 제공하지만 관리자가 입력한 고유 장소명·주소·설명은 원문 유지.
- 기존 상위 폴더 package-lock.json 무시 경고는 빌드 실패가 아니며 외부 파일을 수정하지 않음.
