## 2. 확인된 요구사항과 가정

### 핵심 요구사항

- 콘텐츠 탐색에서 장소 상세, 일정 추가와 편집까지 이어지는 사용자 흐름
- K-콘텐츠·아티스트·관광 장소를 분리한 확장 가능한 데이터 구조
- 한국관광공사 OpenAPI를 주변 관광지와 일정 추천에 실제 활용
- 관리자 인증, 콘텐츠·장소 CRUD, 검수 상태 관리
- CSV 미리보기, 행별 오류 검증, 정상 데이터 저장
- PC 중심 반응형 UI와 한국어·영어 확장 구조

### 현재 가정

- 프레임워크는 Next.js App Router와 TypeScript를 사용한다.
- 패키지 관리자는 현재 설치된 npm을 유지한다.
- 인증과 영속 데이터는 Firebase를 연결할 수 있는 어댑터 구조로 만든다.
- 외부 키가 없는 동안에는 명확히 표시한 데모 데이터로 개발한다.
- 사용자 일정과 찜은 로그인 없이 localStorage에 우선 저장한다.
- 지도 구현은 공급자를 교체할 수 있는 인터페이스를 먼저 만들고, 키 확보 후 Kakao Map을 연결한다.

## 4. 데이터 모델 방향

- `contents`: 작품명, 유형, 설명, 이미지, 공개 상태
- `artists`: 아티스트 기본 정보
- `spots`: 지역, 좌표, 장소 유형, 출처, 확인일, 공개 상태
- `contentPlaces`: 콘텐츠와 장소의 관계 및 근거 설명
- `artistContents`: 아티스트와 콘텐츠 관계
- `itineraries`: 여행 조건과 날짜별 일정 항목
- `tourApiPlaces`: 사용자 기능에 필요한 TourAPI 정규화 캐시

TypeScript 타입, 폼, CSV가 동일한 검증 스키마를 사용하도록 한다. 공개 화면에는 `published` 데이터만 노출한다.

## 5. 외부 API 경계

- 브라우저에서 TourAPI를 직접 호출하지 않는다.
- 서버 Route Handler가 환경변수의 API 키를 사용한다.
- API 응답은 서비스 내부 타입으로 정규화한다.
- timeout, 빈 응답, 인증 오류, 호출 제한을 구분한다.
- 개발 중 데모 응답은 실제 API 데이터와 혼동되지 않도록 표시한다.
- 실제 구현 전 한국관광공사 공식 최신 `Service2` 명세와 필드를 다시 확인한다.

## 8. 2026-09-11 공모전 관점 개선

- 장소 상세 좌표를 TourAPI 주변 관광지 조회에 직접 연결했다.
- 응답을 서비스 내부 타입으로 정규화하고 API 키를 서버 환경변수에만 둔다.
- 실시간 연동 여부와 사용 오퍼레이션을 화면에 표시해 심사 시 데이터 활용을 확인할 수 있게 했다.
- 일정 추천에 지역 35점, 콘텐츠 취향 30점, 비수도권 20점, 직접 선택 100점의 설명 가능한 규칙을 적용했다.
- `docs/api-usage.md`와 `docs/judging-checklist.md`에 연동 증빙과 제출 전 우선순위를 기록했다.
- 홈과 `/map`의 목업 지도를 공통 Kakao Maps 컴포넌트로 교체하고, 키 미설정·SDK 실패 시 기존 디자인 지도를 fallback으로 유지했다. (2026-09-12)
- 홈 지도 중심 반경 10km의 TourAPI 관광지를 불러와 마커와 우측 상세 패널에 연결했다. `현재 지도 내 검색`은 사용자 클릭으로만 다시 조회한다.
- `detailCommon2` 상세조회 라우트를 추가하고 실제 설명·대표 이미지가 있을 때 우측 패널에 표시한다.

### 저장 장소 및 일정 연결 보완

- `/saved`에서 공개 콘텐츠 저장소를 조회해 관리자 등록 장소와 썸네일을 표시한다.
- 저장 장소에서 일정 만들기로 이동하고, 저장 일정은 다시 열어 순서 변경·삭제 후 같은 ID로 저장한다.
- 조회할 수 없는 장소는 누락 안내를 표시하며 해당 장소가 포함된 저장 일정은 편집으로 손실되지 않도록 보관한다.
- 일정 변경 시 저장 상태를 초기화하고 반복 저장 중복을 방지한다. 저장소 접근 실패는 사용자에게 표시한다.
- 일정은 하루 한 장소를 제안하며 부족한 날짜와 이동 시간 미반영 사실을 안내한다.
- 데이터는 해당 브라우저의 localStorage에만 보관되며 다른 기기 동기화는 아직 지원하지 않는다.
- 자동 검증: `node --test tests/*.test.cjs`, lint, TypeScript, production build. 실제 Firebase 데이터 공개부터 브라우저 저장까지의 수동 검수는 별도이다.
